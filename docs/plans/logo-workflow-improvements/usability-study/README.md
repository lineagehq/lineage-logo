## Observing without coaching

Give the participant only the task prompts and shipped product instructions. Read a prompt verbatim if needed; do not explain controls, suggest selection tricks, answer procedural questions, repair the environment or take over. Product help is allowed and its use is counted. A neutral request to state whether the artwork is pending, accepted or durably saved is a scored question, not a hint. Record the controlled identification result, never their spoken words.

For each milestone start the clock when its prompt is presented; stop when the participant declares completion and the observable outcome is checked. Record unaided elapsed seconds (0–1800), retries (0–100), selection retries (0–100), help uses (0–100), assistance and friction codes. A selection retry means an attempted selection that the participant corrects before the requested edit; one undo-and-reselect sequence counts once. A retry means repeating a failed action rather than normal iterative design. Record actual values; at a cap stop the milestone as incomplete with `time_limit` or `retry_limit`, never clamp and claim success. Durations are descriptive baselines, not speed thresholds or proof of improvement.

After a wrong-target edit, data loss or product-caused blocker, stop the counting attempt and retain its unsuccessful receipt. A fix requires regression evidence, a new candidate binding and a new independent unaided attempt; do not rewrite the failed receipt. Maintainer assistance makes the attempt invalid even if the final artwork is correct. Setup or environment failure makes it incomplete; repairing and restarting means a new receipt. Record every attempted milestone; leave unattempted ones explicit. Participant-chosen exploration/Undo is permitted when it causes no wrong-target committed edit or lost work; count retries honestly.

## Assessor oracles (not participant instructions)

Use UI-visible behavior and the installed supported CLI/API, never hidden editor state to perform or rescue an action. After an attempt, independently parse clean saved/exported SVG with a namespace-aware XML parser and render it in a separate viewer. Check unique IDs, resolution of every local resource reference, correct mark/wordmark bounds and the expected manual text/paint/geometry. Compare original bytes with the frozen starting hash. Retain only hashes and controlled outcomes, not SVG payloads in receipts.

| Milestone | Required observable outcome |
| --- | --- |
| `create_import` | Fresh installed candidate creates/imports the supplied fixture without overwriting the preserved original; named mark and text groups are present. |
| `review_reject` | A substantive proposal is visibly pending, participant identifies that state, inspects the difference and rejects with a revision request; accepted SVG and saved files remain unchanged. |
| `review_accept` | Corrected substantive proposal receives explicit acceptance and durable save; participant distinguishes accepted content from pending review and identifies durable saved state; resulting file exists and its digest agrees with the durable receipt. |
| `select_recolor_align` | North seat is located; three intended seat shapes are selected, visibly recolored to the prompt color and aligned left in document coordinates (within 0.5 document unit); unrelated elements retain expected appearance and geometry. |
| `edit_tagline` | Tagline equals the prompted text; other text and manual paint/alignment remain intact. |
| `preserving_followup` | Participant requests a narrow follow-up from current unsaved corrections via fresh bound handoff; after review/acceptance only the specified target changes, all manual corrections survive. |
| `save_restart_reopen` | Participant saves, identifies the saved state, stops/restarts the application process using shipped instructions and reopens the actual saved artifact; independent parse/render matches expected text, paint and geometry, original bytes unchanged. Browser reload alone is insufficient. |
| `export_mark_wordmark` | Participant locates both exported SVG results; separate parser/render checks identify correct subsets, valid references, expected bounds and text; accepted artwork/hash/history state is unchanged by export. |

The producer's frozen follow-up brief must name a target outside the recolored/aligned seats and tagline, and define an exact bounded change. Freeze a pre-follow-up expectation map from the accepted artifact plus the prompted manual changes; compare it with the final parsed result. A matching final digest alone cannot establish preservation or correct target selection. Assessor verification can occur after the clock stops, but cannot repair participant actions.

Use one participant slot per actual person within this local study and a fresh attempt ID each time; no identity map is retained. The user attests distinctness without disclosing identities. Nulls, unknowns and not-attempted checks do not pass. Retries and help use remain visible even in a pass. A correct observed result must support each pass; a subsequent successful milestone cannot fill a missing one.
